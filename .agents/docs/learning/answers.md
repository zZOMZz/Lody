# 参考答案与评分标准

[课程首页](README.md) · [术语表](glossary.md)

先记录自己的答案和实验结果，再打开本页。措辞不用相同，但因果关系和证据必须成立。每章 10 分，8 分以上且关键边界没有误解再继续；只抄输出、无法解释断言不算实验得分。

<a id="day-1"></a>

## 第 1 天

**1.1（2 分）** shared 是复用的代码/协议包，可被不同进程各自加载，1 分；平台能力/外部端口属于 platform，按钮样式属于 ui、会话交互属于 components，举例准确得 1 分。

**1.2（3 分）** 可选功能的背景工作也需遵守能力边界，隐藏 UI 不会停止网络工作，1 分；能力与用户授权分开，1 分；指出本地 renderer/CLI 不应绕开注入的端口直接初始化云服务，1 分。

**1.3（5 分）** 图正确分开 renderer/main/CLI/Agent，2 分；记录实验正常与拒绝结果，1 分；引用 `resolvePlatformKind` 说明空配置选 local、非法值抛错，1 分；说明显式失败可暴露配置错误，1 分。重读[第 1 天导读](day-01-map.md)。

<a id="day-2"></a>

## 第 2 天

**2.1（2 分）** preload 在 renderer 进程中执行而不是独立进程，1 分；TS 类型不验证运行时陌生 JSON，1 分。

**2.2（3 分）** ENOENT 可等待 provisioning，1 分；存在却损坏必须暴露错误，1 分；静默创建空身份会掩盖损坏并打破原子 user/workspace 配对，1 分。

**2.3（5 分）** 在赋值前校验 `next > 100`，1 分；越界后 count 不变，1 分；接着合法调用仍成功，1 分；同时保留非法 channel/类型用例，1 分；定位 `readLocalPlatformSnapshot` 的读取与解析，1 分。典型断言：先加到 99，再加 2 应拒绝，再加 1 得 100；仅断言抛错不够。没有证明 sender 授权是本实验的明确限制。

<a id="day-3"></a>

## 第 3 天

**3.1（2 分）** ACP 为宿主客户端↔编码 Agent，MCP 为 AI 应用的 client↔工具/资源 server，1 分；Session 可包含多个 Turn，1 分。

**3.2（3 分）** unknown 没有证明未投递，自动重试可能重复副作用，1 分；cancel ACK 不是 prompt 已结束/进程已退出，1 分；执行归属与队列推进由执行服务维护，不能由迟到 UI ACK 复活旧 Turn，1 分。把 Stop 等同于 not-applied 则本章不通过。

**3.3（5 分）** 为第二步设置 started/finished 两个明确屏障，1 分；在第二步等待时取消，再手动完成它，1 分；第三步与 persist 未出现而 release 出现，1 分；成功路径包含三步与 persist，1 分；定位生产配置路径的 signal 检查并承认实验没有证明 provider 停止，1 分。检查应放在 await 返回后、后续 mutation 之前，只有最开头检查不能防迟到结果。

<a id="day-4"></a>

## 第 4 天

**4.1（2 分）** 合并状态不等于去重外部副作用，1 分；writer 接受仅通过本地 CRDT 写入契约，落盘由 repository 负责，1 分。

**4.2（3 分）** 一个窗口上传推进 socket 级进度，可能错误认为另一个窗口也已收到，1 分；应按 peer/workspace/room 区分同步，1 分；重启丢掉 dirty 标记但并不丢掉所有本地持久操作，join 应按真实版本重新核对，1 分。

**4.3（5 分）** C 使用独立 peer ID，1 分；记录三方本地修改与交换顺序，1 分；完成后交换各自缺少的操作并断言三份 JSON 一致，1 分；重复 import 不增加项目，1 分；解释没有验证磁盘断电或 Agent exactly-once，1 分。只做 A→B→C→A 未必让 B 得到 C 的操作，还需继续交换。不能把一个碰巧观察到的并发列表顺序当成要求。

<a id="day-5"></a>

## 第 5 天

**5.1（2 分）** 虚拟列表限制 DOM，窗口读取限制正文物化，1 分；初始 snapshot 导入、浅目录仍可能 O(total)，1 分。

**5.2（3 分）** 位置会因结构变化移动，1 分；同 ID 的内容可能已更新，仍要验证 content epoch，1 分；被释放/删除的读取不能重新污染缓存或保留资源，1 分。

**5.3（5 分）** 释放场景通过显式信号控制顺序，1 分；结果返回后不写入，1 分；保留正常接收断言，1 分；性能方案有固定数据量、操作和对照，1 分；区分读取/帧时间/内存指标且说明实验未测真机首屏，1 分。模型可增加 `released` 标志并在接收前检查；生产实现还有多个 lease、membership 与 per-turn epoch，不能把一个全局布尔值直接搬进去。

<a id="day-6"></a>

## 第 6 天

**6.1（2 分）** branch 是 ref，worktree 有工作目录和索引并共享对象库，1 分；端口等外部资源不隔离，1 分。

**6.2（3 分）** 已知归档且清理失败可在保留数据后按策略重试，1 分；元数据不完整时尚不能确定清理资格，1 分；unknown 可能是其他工作空间的活跃会话，保留直到有授权清理的归属证据，1 分。把 unknown 当 deleted 则本章不通过。

**6.3（5 分）** tracked/untracked 恢复而 ignored 不恢复，1 分；原工作目录未被改动，1 分；备份失败就不能删除唯一工作副本，1 分；删除失败保留分支/目录证据，下次协调继续，1 分；指出 `hasCompleteMetadata`、`readOwnerState`、`isRuntimeActive` 与 `archiveWorktree` 的顺序，1 分。恢复成功不代表覆盖了 broken repository、submodule 或其他操作系统行为。

<a id="day-7"></a>

## 第 7 天

**7.1（2 分）** 固定等待依赖调度/负载，既可能没等到事件，也可能掩盖顺序错误，1 分；用 started/finished 信号控制事件，用 fake timers 测时间语义，1 分。

**7.2（3 分）** 输入经业务命令写入历史并发布调度激活，CLI watcher 选择 Turn，execution service 管理 ACP prompt，ACP 通知回写共享数据，renderer reader/store 订阅更新，1 分；说清 renderer↔CLI 的同步与宿主↔Agent 的 ACP 是不同协议，1 分；区分本地接受、存储持久化、投递结论和执行终态，1 分。这是概念链路；新建、继续、steer 有不同分支，不能把它当作唯一实际调用栈。

**7.3（5 分）** 测试层级覆盖选中的故障边界，2 分；替身仅替换明确不可控因素，1 分；最终状态而非调用计数作为主要断言，1 分；拒绝后后续合法操作可成功，1 分。

### 综合作业（20 分）

| 项目       | 满分条件                                                                | 分值 |
| ---------- | ----------------------------------------------------------------------- | ---- |
| 问题与复现 | 有合成输入、具体事件顺序、预期和实际；已有正确行为也如实说明            | 4    |
| 因果链     | 指出 owning module、输入/状态/结束条件，解释边界而非只列文件            | 4    |
| 最小改动   | 不复制协议、旁路 writer 或放宽授权；无重复浅层测试和无关格式变化        | 4    |
| 行为验证   | 成功/失败或竞争路径各有状态断言；控制异步顺序；能说明该测试怎样捕获回归 | 6    |
| 证据限制   | 区分运行通过、仅检查源码和未验证项；附实际命令结果                      | 2    |

16 分为通过线。无论总分多少，若仍把 TS 当运行时校验、CRDT 当副作用去重、取消 ACK 当执行结束、unknown owner 当可删除，则回到对应章节修正后再验收。

没有复现 bug 时，不强行修改实现。一个确有价值且不重复的行为回归也是合格的小改动；最终报告应写“锁定现有行为”，不能写“修复缺陷”。代码改动的合理性和教材实验的通过是两类证据。
