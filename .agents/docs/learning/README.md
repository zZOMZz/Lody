# 七天读懂 Lody：从消息到执行与恢复

这是一套面向开发者的中文源码学习课程。沿着“发送一条消息 → Agent 执行 → 保存结果 → 界面更新”的主线，七天后能够解释核心架构、定位一次故障，并完成有回归验证的小改动。它不要求通读仓库，也不以背诵目录名作为理解标准。

源码核对基线：`4f515900`，2026-09-28。示例与解释对应该版本；后续源码变化时，以链接中的实现、所属 `AGENTS.md` 和当前规范共同核对。学习日按实际开始时间计算，不绑定日历日期。

## 学习范围与前提

- 默认每天 2–3 小时，已会 JavaScript 的函数、对象、数组、Promise，以及基本 Git 操作。TypeScript 和 React 不熟悉时，先完成第 1 天的预备检查。
- 主线是公开仓库的本地桌面构建：Electron、CLI、共享 UI、平台接口和共享数据层。README 中完整产品的云端、Web、移动端能力，不等于本仓库包含其完整实现。
- `Spec` 表达意图，标为 `draft` 的内容不能当作已批准保证；源码说明当前行为，测试说明被覆盖的行为，Note 解释决策背景。通过测试不等于覆盖所有运行环境。
- 课程不改变产品协议或规范。实验使用合成内容和临时目录；参考答案是独立文件，先做题再打开。

每日建议：20 分钟回顾前一章，60 分钟读概念和指定函数，45 分钟实验，25 分钟闭卷练习。第 1 天环境安装可另留时间；概念与轻量实验不依赖完整桌面构建。只有 1 小时时，先做概念、一个实验和第 1 题，把选读与综合改动留到之后；每天 4–6 小时时，再做每章的项目测试与扩展阅读。

不要顺着几千行文件从头读到尾。先回答“谁调用、谁持有状态、什么事件使它结束”，再用 `rg -n '函数名' 路径` 定位。每章指定 2–4 个阅读落点。

## 环境与两种实验

在仓库根目录执行：

```sh
node --version
pnpm --version
git submodule status
```

Node 范围来自根 `package.json`：22.14–22.x 或 23.6+；pnpm 使用其中固定的 10.20.0。子模块行首的 `-` 表示尚未初始化，不是源码文件被删除。完整准备遵循 [贡献指南](../../../CONTRIBUTING.md)：

```sh
git submodule update --init --recursive
pnpm install --frozen-lockfile
```

嵌套 checkout 按根仓库约定跳过安装；独立开发使用自己的 clone。安装成功之后再运行依赖库实验、Vitest 和桌面。本文的命令默认是 macOS/Linux 的 shell；Node 实验本身跨平台，Windows 环境准备参照贡献指南。

**轻量实验**通过 Node 内置断言验证关键概念，无网络、无真实模型调用：

```sh
node --experimental-strip-types .agents/docs/learning/examples/labs.mjs
```

可在末尾加 `1`、`2`、`3` 或 `5` 只运行当天实验。第 1 天直接导入两个项目纯函数模块；其余是明确标注的教学模型，不能代替 Electron、ACP 或 ConversationView 的生产测试。

**依赖库实验**使用仓库安装的 Loro 和 Effect；**项目测试**执行真实模块的既有回归；**桌面体验**才运行完整进程树。各章分别标注命令、预期结果和验证边界。启动方式是 `pnpm start:local`，它会构建嵌入 CLI 和本地 renderer；不是访问一个 Vite 网页。先退出已运行的 Lody，避免单实例行为干扰。

## 如何判断真正理解

每天末尾三题，共 10 分：解释题 2 分、场景推演 3 分、实验或源码证据 5 分。拿到 8 分且没有误解关键边界再进入下一章。低于 8 分按[参考答案](answers.md)指出的落点重读，再换一个输入重做，不能靠背答案补分。

第 7 天综合作业另计 20 分，至少 16 分，并满足：能画出消息往返链路；区分进程、协议与状态归属；用一个失败场景证明改动；诚实写出未验证项。所有章末答案和评分点都在独立答案页。

建议在个人笔记中保留“我的解释、证据位置、实验结果、仍不确定的问题”四栏。不要把真实聊天、凭据或应用数据提交到仓库。
